## Peta Mata Kuliah

Dua dunia pemrograman web yang saling melengkapi:

| Sisi       | Pertemuan | Fokus                                       |
| ---------- | :-------: | ------------------------------------------- |
| **Klien**  |    1–7    | HTML, CSS, JavaScript, Bootstrap, responsif |
| **Server** |   8–14    | PHP, MySQL, CRUD, session, autentikasi      |

**Benang merah:** Sisi klien = antarmuka yang dilihat pengguna. Sisi server = logika, data, dan keamanan di belakangnya. Di akhir semester keduanya bertemu dalam satu aplikasi web utuh dengan CRUD, autentikasi, dan otorisasi.

### Perbandingan Client-side vs Server-side

| Aspek               | Client-side                  | Server-side                      |
| ------------------- | ---------------------------- | -------------------------------- |
| **Lokasi eksekusi** | Browser pengguna             | Server web (Apache/Nginx)        |
| **Bahasa**          | HTML, CSS, JavaScript        | PHP, Python, Node.js, Ruby, Java |
| **Akses database**  | Tidak (langsung)             | Ya                               |
| **Keamanan**        | Kode terlihat user           | Kode tersembunyi dari user       |
| **Beban**           | CPU user                     | CPU server                       |
| **Contoh**          | Validasi form, animasi, AJAX | Login, olah data, kirim email    |

### Contoh Kode

<details>
<summary>HTML Form — Input dasar dan proses submit</summary>

```html
<form action="proses.php" method="POST">
    <label for="nama">Nama:</label>
    <input type="text" id="nama" name="nama" required />

    <label for="email">Email:</label>
    <input type="email" id="email" name="email" required />

    <button type="submit">Kirim</button>
</form>
```

**Penjelasan:**

- `action` = file PHP yang akan memproses data
- `method="POST"` = kirim data via body request (bukan URL)
- `id` = untuk `label for` (aksesibilitas)
- `name` = nama field yang dikirim ke server
- `required` = HTML5 validation client-side

</details>

<details>
<summary>CRUD PHP + MySQL — Insert, Read, Update, Delete dengan prepared statement</summary>

```php
<?php
// koneksi
$conn = new mysqli('localhost', 'root', '', 'rpl105');

// CREATE
$stmt = $conn->prepare("INSERT INTO mahasiswa (nama, email) VALUES (?, ?)");
$stmt->bind_param("ss", $nama, $email);
$stmt->execute();

// READ
$result = $conn->query("SELECT * FROM mahasiswa ORDER BY id DESC");

// UPDATE
$stmt = $conn->prepare("UPDATE mahasiswa SET nama = ? WHERE id = ?");
$stmt->bind_param("si", $nama, $id);
$stmt->execute();

// DELETE
$stmt = $conn->prepare("DELETE FROM mahasiswa WHERE id = ?");
$stmt->bind_param("i", $id);
$stmt->execute();
?>
```

**Kenapa Prepared Statement?**

- **Cegah SQL Injection** — parameter tidak di-escape manual, tapi di-bind aman.
- **Reusable** — statement bisa di-`execute()` berkali-kali dengan parameter beda.
- **Performa** — database bisa cache query plan.

`bind_param("ss", ...)` — arti `s`/`i`/`d`/`b`:
| Kode | Tipe |
| ---- | ------------- |
| `s` | String |
| `i` | Integer |
| `d` | Double (float)|
| `b` | Blob (binary) |

</details>

<details>
<summary>Login dengan Password Hashing — Registrasi & autentikasi aman</summary>

```php
<?php
// register
$hash = password_hash($_POST['password'], PASSWORD_BCRYPT);
$stmt = $conn->prepare("INSERT INTO users (username, password_hash) VALUES (?, ?)");
$stmt->bind_param("ss", $_POST['username'], $hash);
$stmt->execute();

// login
$stmt = $conn->prepare("SELECT id, username, password_hash FROM users WHERE username = ?");
$stmt->bind_param("s", $_POST['username']);
$stmt->execute();
$user = $stmt->get_result()->fetch_assoc();

if ($user && password_verify($_POST['password'], $user['password_hash'])) {
    session_start();
    $_SESSION['user_id'] = $user['id'];
    header('Location: dashboard.php');
    exit;
}
?>
```

**Poin Keamanan Kritis:**

- **Jangan simpan password plaintext** — selalu hash dengan `password_hash()`.
- **`PASSWORD_BCRYPT`** — algoritma standar, salt otomatis, adaptive cost.
- **`password_verify()`** — bandingkan input user dengan hash tersimpan.
- **`session_start()`** — mulai session untuk tracking user yang login.
- **`header('Location: ...')`** — redirect; wajib diikuti `exit`.
- **`exit`** — stop eksekusi agar kode di bawah tidak jalan.

</details>

<details>
<summary>Validasi Server-side — Cek input sebelum diproses</summary>

```php
<?php
$errors = [];

if (empty($_POST['nama'])) {
    $errors[] = 'Nama wajib diisi.';
}

if (!filter_var($_POST['email'], FILTER_VALIDATE_EMAIL)) {
    $errors[] = 'Email tidak valid.';
}

if (strlen($_POST['password']) < 8) {
    $errors[] = 'Password minimal 8 karakter.';
}

if (empty($errors)) {
    // lanjut proses simpan
} else {
    // tampilkan $errors ke user
}
?>
```

**Kenapa validasi di server?**

- Validasi HTML5 (`required`, `type="email"`) bisa **dilewati** dengan disable JS atau tool.
- Validasi server-side adalah **satu-satunya** validasi yang benar-benar dipercaya.
- Validasi client-side hanya untuk UX, bukan security.

</details>

<details>
<summary>Upload File — Validasi MIME, size, dan simpan aman</summary>

```php
<?php
$allowed = ['image/jpeg', 'image/png', 'image/gif'];
$maxSize = 2 * 1024 * 1024; // 2 MB

if ($_FILES['foto']['error'] !== UPLOAD_ERR_OK) {
    die('Upload gagal.');
}

if (!in_array($_FILES['foto']['type'], $allowed)) {
    die('Tipe file tidak diizinkan.');
}

if ($_FILES['foto']['size'] > $maxSize) {
    die('File terlalu besar.');
}

$ext = pathinfo($_FILES['foto']['name'], PATHINFO_EXTENSION);
$filename = uniqid('img_', true) . '.' . $ext;
$dest = __DIR__ . '/uploads/' . $filename;

if (move_uploaded_file($_FILES['foto']['tmp_name'], $dest)) {
    echo "Berhasil: $filename";
}
?>
```

**Risiko upload file:**

- **Arbitrary file upload** — user upload `.php` lalu eksekusi.
- **XSS via SVG** — SVG bisa berisi script.
- **Path traversal** — filename `../../etc/passwd`.
- **DoS** — upload file raksasa.

Mitigasi: whitelist MIME, batasi size, rename file dengan nama acak, simpan di luar webroot.

</details>

## Tips Praktis

:::tip Strategi Belajar RPL105

- **Ketik ulang, jangan copy-paste** — muscle memory penting untuk HTML/CSS/JS.
- **Buka DevTools setiap saat** — inspect element, console, network adalah teman.
- **Commit Git tiap pertemuan** — version control dari awal, bukan akhir.
- **Uji di banyak browser** — Chrome, Firefox, Safari punya quirks berbeda.
- **Mulai dari struktur** — HTML dulu, CSS kedua, JS ketiga.
- **Server-side butuh sabar** — debugging PHP tanpa error messages jelas butuh latihan.
- **Amankan sejak awal** — prepared statement, password_hash, validasi server.

:::

:::warning Jebakan Umum

- **Lupa `exit` setelah `header('Location: ...')`** → kode tetap jalan.
- **SQL injection** karena query manual dengan concat string.
- **Simpan password plaintext** — fatal.
- **Tidak validasi input server-side** — percaya validasi HTML5.
- **Copy-paste kode tanpa paham** — debugging jadi mimpi buruk.
- **Tidak pakai version control** — kehilangan kode saat laptop rusak.
- **Hapus database production** tanpa backup.

:::
