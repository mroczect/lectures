## Deskripsi

Konsep dasar web dengan **client side** (HTML, CSS, JavaScript, responsif) dan **server side** (PHP, MySQL). Mahasiswa membangun aplikasi web dari halaman statis hingga sistem autentikasi lengkap dengan database.

SKS terbesar di semester 1. Beban praktikum paling padat.

## Client-side vs Server-side

| Aspek           | Client-side                  | Server-side                      |
| --------------- | ---------------------------- | -------------------------------- |
| Lokasi eksekusi | Browser pengguna             | Server web (Apache/Nginx)        |
| Bahasa          | HTML, CSS, JavaScript        | PHP, Python, Node.js, Ruby, Java |
| Akses database  | Tidak (langsung)             | Ya                               |
| Keamanan        | Kode terlihat user           | Kode tersembunyi dari user       |
| Beban           | CPU user                     | CPU server                       |
| Contoh          | Validasi form, animasi, AJAX | Login, olah data, kirim email    |

## Tujuan Pembelajaran

1. Menjelaskan teknologi web & membedakan client-side vs server-side.
2. Mengimplementasikan HTML, CSS, JS untuk antarmuka interaktif.
3. Menerapkan standar coding (deskripsi file, penamaan).
4. Menggunakan framework front-end untuk web responsif.
5. Menggunakan bahasa pemrograman untuk mengolah & memvalidasi data.
6. Mengimplementasikan CRUD dengan basis data.
7. Mengimplementasikan pengolahan file, autentikasi, otorisasi (session/cookie).

## Contoh Kode

### HTML Form

```html
<form action="proses.php" method="POST">
    <label for="nama">Nama:</label>
    <input type="text" id="nama" name="nama" required />

    <label for="email">Email:</label>
    <input type="email" id="email" name="email" required />

    <button type="submit">Kirim</button>
</form>
```

-   `action` — file PHP yang memproses data.
-   `method="POST"` — kirim via body request, bukan URL.
-   `id` — untuk `label for` (aksesibilitas).
-   `name` — nama field yang dikirim ke server.
-   `required` — validasi HTML5 client-side.

### CRUD PHP + MySQL dengan Prepared Statement

```php
<?php
// koneksi
$conn = new mysqli('localhost', 'root', '', 'rpl105');

// CREATE
$stmt = $conn->prepare("INSERT INTO mahasiswa (nama, email) VALUES (?, ?)");
$stmt->bind_param("ss", $nama, $email);
$stmt->execute();

// READ
$result = $conn->query("SELECT * FROM mahasiswa ORDER BY id DESC");

// UPDATE
$stmt = $conn->prepare("UPDATE mahasiswa SET nama = ? WHERE id = ?");
$stmt->bind_param("si", $nama, $id);
$stmt->execute();

// DELETE
$stmt = $conn->prepare("DELETE FROM mahasiswa WHERE id = ?");
$stmt->bind_param("i", $id);
$stmt->execute();
?>
```

Prepared statement mencegah SQL injection — parameter di-bind aman, bukan di-concat string. Statement juga bisa di-`execute()` berkali-kali dengan parameter berbeda.

Kode tipe di `bind_param`:

| Kode | Tipe           |
| :--: | -------------- |
| `s`  | String         |
| `i`  | Integer        |
| `d`  | Double (float) |
| `b`  | Blob (binary)  |

### Login dengan Password Hashing

```php
<?php
// register
$hash = password_hash($_POST['password'], PASSWORD_BCRYPT);
$stmt = $conn->prepare("INSERT INTO users (username, password_hash) VALUES (?, ?)");
$stmt->bind_param("ss", $_POST['username'], $hash);
$stmt->execute();

// login
$stmt = $conn->prepare("SELECT id, username, password_hash FROM users WHERE username = ?");
$stmt->bind_param("s", $_POST['username']);
$stmt->execute();
$user = $stmt->get_result()->fetch_assoc();

if ($user && password_verify($_POST['password'], $user['password_hash'])) {
    session_start();
    $_SESSION['user_id'] = $user['id'];
    header('Location: dashboard.php');
    exit;
}
?>
```

Poin keamanan:

-   Jangan simpan password plaintext — hash dengan `password_hash()`.
-   `PASSWORD_BCRYPT` — salt otomatis, adaptive cost.
-   `password_verify()` — bandingkan input user dengan hash tersimpan.
-   `header('Location: ...')` wajib diikuti `exit` — kalau tidak, kode di bawahnya tetap jalan.

### Validasi Server-side

```php
<?php
$errors = [];

if (empty($_POST['nama'])) {
    $errors[] = 'Nama wajib diisi.';
}

if (!filter_var($_POST['email'], FILTER_VALIDATE_EMAIL)) {
    $errors[] = 'Email tidak valid.';
}

if (strlen($_POST['password']) < 8) {
    $errors[] = 'Password minimal 8 karakter.';
}

if (empty($errors)) {
    // lanjut proses simpan
}
?>
```

Validasi HTML5 (`required`, `type="email"`) bisa dilewati dengan disable JS atau tool. Validasi server-side adalah satu-satunya validasi yang bisa dipercaya. Validasi client-side hanya untuk UX.

### Upload File

```php
<?php
$allowed = ['image/jpeg', 'image/png', 'image/gif'];
$maxSize = 2 * 1024 * 1024; // 2 MB

if ($_FILES['foto']['error'] !== UPLOAD_ERR_OK) {
    die('Upload gagal.');
}

if (!in_array($_FILES['foto']['type'], $allowed)) {
    die('Tipe file tidak diizinkan.');
}

if ($_FILES['foto']['size'] > $maxSize) {
    die('File terlalu besar.');
}

$ext = pathinfo($_FILES['foto']['name'], PATHINFO_EXTENSION);
$filename = uniqid('img_', true) . '.' . $ext;
$dest = __DIR__ . '/uploads/' . $filename;

if (move_uploaded_file($_FILES['foto']['tmp_name'], $dest)) {
    echo "Berhasil: $filename";
}
?>
```

Risiko upload file: arbitrary file upload (user upload `.php`), XSS via SVG, path traversal (`../../etc/passwd`), DoS dari file raksasa. Mitigasi: whitelist MIME, batasi size, rename dengan nama acak, simpan di luar webroot.
