## 2. Data dan Datum

-   **Data** — dari bahasa Latin, bentuk jamak dari **datum**.
-   **Datum** — satu fakta tunggal.
-   **Data** — kumpulan fakta dalam berbagai format.
-   **Data tidak bermakna sampai ditafsirkan.**

Contoh tabel:

| Nama Sekolah | Jumlah Siswa | Kondisi Sekolah |
| :----------- | -----------: | :-------------- |
| A            |          100 | Baik            |
| B            |          125 | Sedang          |
| C            |          250 | Baik            |
| D            |          300 | Baik            |
| E            |          175 | Baik            |

Satu sel (`100`) adalah datum. Keseluruhan tabel adalah data.

### Piramida Data

| Tingkat     | Definisi                              | Contoh                                              |
| ----------- | ------------------------------------- | --------------------------------------------------- |
| Datum       | Fakta tunggal, mentah, belum bermakna | `100`                                               |
| Data        | Kumpulan datum terorganisir           | Tabel jumlah siswa 5 sekolah                        |
| Informasi   | Data yang sudah diolah & bermakna     | "Sekolah D punya siswa terbanyak (300 orang)."      |
| Pengetahuan | Pola/kesimpulan yang bisa diambil     | "Sekolah besar cenderung punya kondisi lebih baik." |

## 3. Apa Itu Database?

Kumpulan data besar yang terintegrasi, terstruktur, dan memodelkan objek dunia nyata sehingga pengguna dapat mengambil informasi dengan cepat.

Database memodelkan dua hal:

1. **Entity** — objek seperti orang, barang, atau identitas. Contoh: Tony, Mahasiswa, Produk.
2. **Relationship** — hubungan antar entitas. Contoh: Tony tinggal di Jl. Ahmad Yani.

Etimologi:

| Kata     | Arti                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| Data     | Fakta atau informasi untuk menghitung, menganalisis, atau merencanakan               |
| Base     | Sesuatu yang menjadi tempat atau penopang                                            |
| Database | Kumpulan besar data terorganisir untuk pencarian dan pengambilan cepat oleh komputer |

Karakteristik database yang baik:

-   **Terintegrasi** — data saling terhubung, tidak terisolasi.
-   **Terstruktur** — ada skema yang jelas, bukan tumpukan file acak.
-   **Memodelkan dunia nyata** — merepresentasikan entitas dan relasi yang sesungguhnya.
-   **Dapat di-query** — pengguna bisa mengambil informasi secara cepat dan terarah.

## 4. Tujuan Database

| Tujuan           | Penjelasan                                           |
| ---------------- | ---------------------------------------------------- |
| Speed            | Menyimpan, memanipulasi, mengambil data dengan cepat |
| Space efficiency | Mengurangi redundansi dengan relasi antar tabel      |
| Accuracy         | Data constraint agar data unik dan konsisten         |
| Availability     | Data selalu tersedia saat dibutuhkan                 |
| Completeness     | Bisa menambahkan data atau struktur baru             |
| Security         | User management — siapa boleh mengakses apa          |
| Sharability      | Banyak pengguna berbagi database yang sama           |

## 5. Tahapan Desain Database

Need Analysis → Data Model (ER) → Relational Schema → DBMS + Query

| Tahap                | Penjelasan                                                 |
| -------------------- | ---------------------------------------------------------- |
| 1. Need Analysis     | Menganalisis kebutuhan sistem dan data yang harus disimpan |
| 2. Data Model (ER)   | Membuat model konseptual dengan ER Diagram                 |
| 3. Relational Schema | Menerjemahkan ER Diagram menjadi skema tabel relasional    |
| 4. DBMS + Query      | Implementasi skema ke DBMS dan menulis query SQL           |

Urutannya penting: salah di Need Analysis → model data salah → skema salah → implementasi salah. Jangan langsung menulis SQL — rancang dulu di tingkat konseptual.

## 6. Excel vs Relational Database

Studi kasus: Politeknik dengan ribuan data mahasiswa, mata kuliah, dosen, kelas, dan nilai.

**Kelebihan Excel:**

-   Sederhana dan mudah dipakai.
-   Mudah dibagikan.
-   Mudah insert, edit, delete.
-   Ada fitur Find.
-   Mudah di-backup.

**Kelemahan Excel:**

-   File besar → lambat.
-   Data redundancy — data sama tersimpan berulang.
-   Relasi data sulit. Contoh: "Mahasiswa mana saja yang mengambil Basis Data?"
-   Penambahan kolom menyulitkan struktur.
-   Analisis data sulit. Contoh: "Berapa mahasiswa yang tinggal di Batam Center?"
-   Data versioning manual.
-   Security lemah — nilai mahasiswa hanya boleh diedit dosen tertentu, sulit diatur.

**Solusi dari RDB:**

| Masalah Excel    | Solusi RDB                           |
| ---------------- | ------------------------------------ |
| File size besar  | Data terdistribusi di banyak tabel   |
| Data redundancy  | Relasi antar tabel                   |
| Relasi sulit     | Foreign key + JOIN                   |
| Struktur kaku    | `ALTER TABLE` untuk tambah kolom     |
| Analisis susah   | `SELECT` + agregasi (`SUM`, `COUNT`) |
| Tidak multi-user | User management + transaction        |
| Keamanan lemah   | `GRANT` / `REVOKE` per user          |

## 7. Relational Database (RDB)

Kumpulan data yang diorganisir dalam bentuk tabel, record, dan kolom, dengan hubungan terdefinisi baik antar tabel.

Karakteristik:

-   Tabel saling berkomunikasi dan berbagi informasi.
-   Memudahkan pencarian, pengorganisasian, dan pelaporan data.
-   Menggunakan Structured Query Language (SQL).
-   Berasal dari konsep fungsi matematis tentang pemetaan himpunan data.

Komponen:

| Komponen             | Deskripsi                                |
| -------------------- | ---------------------------------------- |
| Tabel (relation)     | Kumpulan data tentang satu jenis entitas |
| Baris (tuple/record) | Satu instance data dalam tabel           |
| Kolom (attribute)    | Properti dari entitas                    |
| Primary key          | Kolom yang mengidentifikasi baris unik   |
| Foreign key          | Kolom yang merujuk ke PK tabel lain      |
| Relasi               | Hubungan logis antar tabel via key       |

### Contoh

**Tabel MHSN:**

| NPM      | Nama         | Alamat  |
| -------- | ------------ | ------- |
| 10296832 | Nurhayati    | Jakarta |
| 10296126 | Astuti       | Jakarta |
| 1296500  | Budi         | Depok   |
| 1296525  | Prananingrum | Bogor   |
| 96487    | Pipit        | Bekasi  |
| 96353    | Quraish      | Bogor   |

**Tabel MKUL:**

| KDMK  | MTKULIAH      | SKS | KK    |
| ----- | ------------- | --: | ----- |
| KK021 | P. Basis Data |   2 | KD132 |
| SIM   | 3             |     |       |
| KU122 | Pancasila     |   2 |       |

**Tabel NILAI:**

| NPM      | KDMK  | MID | FINAL |
| -------- | ----- | --: | ----: |
| 10296832 | KK021 |  60 |    75 |
| 10296126 | KD132 |  70 |    90 |
| 1296500  | KK021 |  55 |    40 |
| 1296525  | KU122 |  90 |    80 |
| 1196353  | KU122 |  75 |    75 |
| 96487    | KD132 |  80 |     0 |
| 10296832 | KD132 |  40 |    30 |

NPM dan KDMK menjadi penghubung antar tabel — inilah yang disebut relasi.

Query contoh:

```sql
-- Siapa saja mahasiswa yang tinggal di Bogor?
SELECT Nama, Alamat FROM MHSN WHERE Alamat = 'Bogor';

-- Berapa nilai akhir Nurhayati di P. Basis Data?
SELECT m.Nama, mk.MTKULIAH, n.FINAL
FROM MHSN m
JOIN NILAI n ON m.NPM = n.NPM
JOIN MKUL m k ON n.KDMK = mk.KDMK
WHERE m.Nama = 'Nurhayati' AND mk.MTKULIAH = 'P. Basis Data';
```

## 8. Database Management System (DBMS)

Perangkat lunak yang menggunakan metode standar untuk katalogisasi, pengambilan, dan menjalankan query pada data.

Fungsi:

-   Mengelola data yang masuk.
-   Mengorganisir data.
-   Menyediakan cara agar data dapat dimodifikasi atau diekstraksi oleh pengguna atau program lain.

DBMS populer:

| DBMS             | Karakteristik                                             |
| ---------------- | --------------------------------------------------------- |
| MySQL            | Open source, populer untuk web                            |
| PostgreSQL       | Open source, fitur lengkap, mendukung kompleksitas tinggi |
| Microsoft Access | Cocok untuk desktop dan data kecil                        |
| SQL Server       | Produk Microsoft, umum di enterprise                      |
| Oracle           | Enterprise-grade, sangat skalabel                         |

Komponen sistem database:

1. Database — kumpulan datanya.
2. DBMS — perangkat lunaknya.
3. Hardware — server/komputer.
4. Sistem operasi.
5. User — pengguna.
6. Aplikasi pendukung.

Tugas utama DBMS:

| Tugas             | Penjelasan                                         |
| ----------------- | -------------------------------------------------- |
| Data definition   | Mendefinisikan struktur (DDL: CREATE, ALTER, DROP) |
| Data manipulation | Mengelola isi data (DML: INSERT, UPDATE, DELETE)   |
| Data query        | Mengambil data (DQL: SELECT)                       |
| Access control    | Mengatur hak akses (DCL: GRANT, REVOKE)            |
| Transaction       | Menjaga konsistensi (COMMIT, ROLLBACK)             |
| Backup & recovery | Menyalin & memulihkan data jika gagal              |
